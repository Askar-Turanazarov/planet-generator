# Planet Generator 3D — план реализации

Процедурный генератор планет AAA-уровня в реальном времени: Three.js r170 + собственные GLSL-шейдеры.
Ни одной внешней текстуры, модели или звука — всё синтезируется на GPU из 3D-шума.

Статусы: `[ ]` — не начато, `[~]` — в работе, `[x]` — готово и проверено в браузере.

**Состояние: все шаги выполнены**, включая второй проход по производительности и качеству картинки (шаг 12)
три языка интерфейса — английский, русский, узбекский (шаг 13) — и адаптацию под телефоны и планшеты
с подготовкой к деплою на Vercel (шаг 14; подробности — в [DEPLOY-PLAN.md](DEPLOY-PLAN.md)), а также оптимизация по итогам
аудита (шаг 15: Three.js в проекте, фоновая компиляция шейдеров, профиль `high` для новых iPhone/iPad, регулятор разрешения)
и фундамент для следующих идей (шаг 16: зонд по касанию, мир в адресе страницы, карточки), а также экскурсии
и «почему здесь так» (шаг 17).
Сам Vercel не подключён — ждёт решения владельца. Что именно проверено и чем — в разделе 3.

Документы проекта лежат в `docs/`: `plans/` — действующие планы (этот файл и DEPLOY-PLAN.md), `ideas/` — варианты
улучшений на обсуждение, `archive/` — отработанные или отклонённые планы.

## 0. Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Один файл или несколько | Исходники — модулями в `src/`, плюс скрипт сборки в единую страницу (`dist/index.html` для хостинга и она же как `dist/planet-generator.html`) | Модули проще отлаживать (ошибка шейдера указывает на конкретный файл), а готовый single-file открывается двойным кликом |
| Three.js | `three@0.170.0` через import map из `vendor/three-0.170.0/` (копия из реестра npm, `tools/vendor-three.mjs`) | Требование ТЗ: r170+, ES-модули, аддоны `OrbitControls`/`EffectComposer`/…; своя копия — без зависимости от CDN, работа офлайн (шаг 15) |
| Шум | 3D Simplex (Ashima/McEwan, с аналитическим градиентом) по координатам единичной сферы | Нет UV — нет швов и стягивания к полюсам |
| **Кэш процедурных полей** | Дорогие поля (рельеф, климат, огни городов, облака, профиль колец, туманность) синтезируются из 3D-шума в кубические карты и LUT; покадровые шейдеры их только читают | Первая версия считала ~70 выборок шума на пиксель каждый кадр: 54 мс/кадр на Intel UHD. С кэшем — ≈ 6 мс при 1080p. Кубкарта адресуется тем же 3D-направлением, поэтому швов по-прежнему нет |
| Когда кэш пересчитывается | Только при смене seed/архетипа, под «затемнением» экспозиции, порциями по кадрам. Слайдеры кэш не трогают | Уровень моря, рельеф, лёд, огни, облачность, палитра остаются живыми uniform-ами → 60 FPS при перетаскивании, ноль пересборок |
| Рельеф | Bump по 3 пробам высоты в object space (`h(p)`, `h(p+εT)`, `h(p+εB)`), без смещения вершин; вблизи — микрорельеф из 3 октав с аналитическим градиентом, включаемый по LOD | Требование ТЗ; силуэт остаётся идеальной сферой под атмосферой |
| Облака во времени | Три снимка поля (прошлый/текущий/следующий); следующий запекается по нескольку строк текселей за кадр, равномерно за 3 с, шейдеры смешивают два готовых | Погода плавно эволюционирует, а стоимость одинакова в каждом кадре — без периодических подёргиваний |
| Атмосфера | Численное интегрирование однократного рассеяния (Rayleigh + Mie) по лучу в оболочке `1.065`; оптическая глубина к солнцу — из таблицы, посчитанной на CPU | Физика сама даёт яркий лимб, закатный сдвиг на терминаторе и черноту ночной стороны |
| Сглаживание краёв | Аналитическое покрытие силуэта (`limbCoverage`) вместо MSAA | MSAA×4 на HDR-буфере стоил ~8 мс на встроенной графике; аналитический край бесплатен и точнее |
| Запас по производительности | Регулятор разрешения (0.5–1.0 от выбранного Render Scale): сам определяет частоту монитора и держит время GPU в 80 % от интервала кадра; на экранах ≥ 100 Гц при нехватке переходит на половинную частоту вместо сильного размытия. Блум в половинном разрешении | Слабый GPU теряет пиксели, а не кадры; нагрузка меряется таймером GPU (`EXT_disjoint_timer_query_webgl2`), поэтому свёрнутое или придержанное браузером окно не принимается за «слабую видеокарту» |
| Параметры | Все настройки — `uniforms`, общие объекты `{value}` для всех материалов (включая запекающие) | Слайдеры не пересоздают геометрию и материалы → нет утечек |
| Плавность | Каждое числовое значение и цвет экспоненциально сглаживаются к цели | Слайдеры и пресеты «перетекают», а не щёлкают |
| Кольца и атмосфера | Кольцо рисуется двумя проходами (дальняя половина → атмосфера → ближняя половина) | Корректная сортировка полупрозрачного кольца относительно аддитивного ореола |
| Языки интерфейса | Все видимые тексты — в одном словаре `src/i18n.js` (EN / RU / UZ) по ключам; HUD и `main.js` знают только ключи. Смена языка перекрашивает подписи на месте, без пересборки панелей и без перезагрузки | Перевод правится в одном файле; новый язык — это ещё один блок словаря и строка в `LANGUAGES` |

## 2. Шаги реализации

### Шаг 1. Каркас
- [x] `index.html`: import map (`three`, `three/addons/`), `<canvas>`, контейнеры HUD.
- [x] `css/hud.css`: панели `rgba(10,12,16,0.78)` + `backdrop-filter: blur(12px)` + рамка `1px rgba(255,255,255,0.12)`, моноширинный шрифт, `tabular-nums`, без декоративных градиентов.
- [x] Локальный статический сервер (`tools/serve.mjs`, Node без зависимостей) и `.claude/launch.json`.

### Шаг 2. Общие GLSL-блоки (`chunks.js`)
- [x] `snoiseD`/`snoise` — 3D Simplex с аналитическим градиентом; `fbm` с дробным числом октав; `ridgedMF` — ридж-мультифрактал.
- [x] `hash33` + `voronoi` (F1, F2, id ячейки) — для городов и дорог.
- [x] `sunTransmit(mu)`, `viewExtinction` — цвет солнечного света и воздушная перспектива.
- [x] `ggxSpec` — GGX-блик; `limbCoverage` — аналитическое сглаживание силуэта.
- [x] Синтез и чтение полей: `terrainFields`, `cloudFieldSynth` → `cloudDensity`, `ringField` → `ringShadow` — общие для всех шейдеров, поэтому тени облаков и колец совпадают с самими облаками и кольцами.

### Шаг 3. Поверхность (`SphereGeometry(1, 192, 192)`)
- [x] Высота: domain warping (вектор из трёх fBm) → континентальный fBm → ридж-горы по маске суши → каньоны/трещины/лавовые реки («жилы») → дюны. Синтезируется в кэш; итог = база + рельеф × горы (слайдер рельефа живой).
- [x] Нормаль: 3 пробы (`h(p)`, `h(p+εT)`, `h(p+εB)`), ε привязан к размеру пикселя; вблизи добавляется микрорельеф по LOD.
- [x] Океан: градиент глубины (абиссаль → шельф), анимированная рябь, GGX-блик только на воде и льду, френелевское отражение неба.
- [x] Суша: песок побережья → влажные/сухие низины (влажность + пояс пустынь) → холодные широты → слоистая скала (по высоте и крутизне) → снег (линия снега зависит от широты, на кручах снега нет) → полярные шапки. На сухих мирах биомы отсчитываются от фиксированной отметки, а не от «ушедшего» моря.
- [x] Ночные огни: три масштаба Voronoi — точечные «фонари» размером с тексель, из которых собраны посёлки и мегаполисы с рваным контуром и редеющей окраиной, плюс «трассы»-бусы по рёбрам ячеек; маска по побережью, низинам, умеренным широтам; `smoothstep` через терминатор — днём невидимы.
- [x] Лава (Mustafar): эмиссивные «моря» с коркой и трещинами + эмиссивные реки.
- [x] Тени: облаков (проекция к солнцу на высоту облачного слоя), колец и рельефа (у терминатора — две пробы высоты вдоль луча солнца).

### Шаг 4. Облака (`SphereGeometry(1.012, 128, 128)`)
- [x] Анимированный domain-warped fBm, вытянутый по широте (полосы и перистые штрихи).
- [x] Три циклона: закручивание области вокруг центров, зависящих от seed, знак — по полушарию.
- [x] Самозатенение: вторая проба плотности со сдвигом к солнцу.
- [x] Собственное вращение слоя, независимое от поверхности.
- [x] Эволюция во времени через три снимка поля с покадровым запеканием строк; у каждой октавы свой дрейф, чтобы снимки смешивались без пульсации мелких деталей.

### Шаг 5. Атмосфера (`SphereGeometry(1.065, 128, 128)`, `BackSide`, `AdditiveBlending`)
- [x] Пересечения луча со сферами атмосферы и планеты; 12 шагов по лимбу, 7 (сгущённых к поверхности) — по лучам, упирающимся в планету; оптическая глубина к солнцу — из LUT.
- [x] Фазовые функции Рэлея и Ми (Henyey–Greenstein), тень планеты.
- [x] Дизеринг шага для подавления полос.
- [x] Плотность и сдвиг оттенка пересчитываются в коэффициенты рассеяния в JS.

### Шаг 6. Кольца (`RingGeometry`, включаются тумблером)
- [x] Радиальный профиль: шум на 4 частотах (микрополосы), щели в духе деления Кассини, пылевые полосы, мягкие края.
- [x] Аналитическая тень планеты (луч–сфера) с полутенью и покраснением у края от атмосферы.
- [x] Освещённая/теневая сторона, прямое рассеяние при контровом свете.
- [x] Два прохода (дальняя/ближняя половина) для правильной сортировки с атмосферой.

### Шаг 7. Космос и пост-обработка
- [x] Небесная сфера: три слоя звёзд с цветовой температурой, приглушённая галактическая полоса с пылевыми прожилками (запечена один раз), диск солнца.
- [x] `EffectComposer`: `RenderPass` → `UnrealBloomPass(strength 0.35, radius 0.4, threshold 0.85)` → `OutputPass` (ACES Filmic, экспозиция 1.05), HDR-буфер HalfFloat. Свечение блума подмешивается прямо в `OutputPass` (на один полноэкранный проход меньше), там же — дизеринг против полос в тёмных градиентах.

### Шаг 8. HUD и управление
- [x] Архетипы в один клик: Terran Prime, Arrakis Arid, Mustafar Volcanic, Europa Cryo, Kepler Super-Earth.
- [x] Seed (число или строка) + Randomize.
- [x] Слайдеры: уровень моря, рельеф, полярный лёд, огни цивилизации, облачность, плотность атмосферы, сдвиг оттенка, кольца (вкл/наклон), угол солнца, скорость вращения, Render Scale.
- [x] Ракурсы камеры: Orbital Overview, Terminator Close-Up, Night Side Cities, Ring Plane — плавный перелёт.
- [x] `[H]` — кинематографический режим без интерфейса; `1–5` — архетипы; `R` — случайный seed.
- [x] Телеметрия: FPS, время кадра, время GPU, разрешение, высота камеры, фазовый угол, LOD рельефа, статус синтеза.

### Шаг 9. Производительность (добавлен по результатам замеров)
- [x] Кэширование полей в кубкарты и LUT (`src/bake.js`, `src/shaders/bake.js`).
- [x] Пересинтез мира порциями под затемнением экспозиции; слайдеры без пересинтеза.
- [x] Аналитическое сглаживание лимба вместо MSAA, блум в половинном разрешении, регулятор разрешения.
- [x] Восстановление кэшей после потери WebGL-контекста.

### Шаг 10. Проверка и доводка
- [x] Нет ошибок компиляции GLSL (все пять архетипов, кольца вкл/выкл).
- [x] Скриншоты каждого архетипа и каждого ракурса, визуальная доводка палитр, облаков и яркостей.
- [x] Resize окна: `renderer` + `composer` + `camera.aspect`.
- [x] Блум не «выжигает» дневную сторону; ночная сторона без светящегося контура.

### Шаг 11. Сборка single-file
- [x] `node tools/build-single.mjs` → `dist/planet-generator.html` (один файл, открывается двойным кликом; с шага 15 Three.js тоже внутри — ≈ 910 kB, интернет не нужен). Страница сайта `dist/index.html` — ≈ 175 kB, Three.js к ней — отдельными файлами из `dist/vendor/`.

### Шаг 12. Второй проход: скорость и качество картинки
Скорость:
- [x] Замер по частям таймером GPU (пакетный бенчмарк, чередование «старая сборка / новая» между загрузками страницы).
- [x] Регулятор разрешения переписан: цель — частота монитора, нагрузка — по времени GPU, защита от придержанного окна.
- [x] Запекание облаков — равномерно по строкам; после пересинтеза мира печётся один снимок вместо двух.
- [x] Блум сведён в `OutputPass`; у рендерера убраны ненужные alpha/depth/stencil основного буфера.
- [x] Небо не считается за диском планеты; атмосфера не интегрируется там, где весь луч лежит в тени планеты.
- [x] Микрорельеф и эрозия облаков гаснут на ночной стороне; рябь океана считается только вокруг солнечного блика.

Качество:
- [x] Кэш облаков 768² (было 512²), 7 октав, более чёткий порог; вблизи край облака дополнительно собирается.
- [x] Облака освещаются как рельеф (наклон поля вдоль луча солнца), а не только по кромке.
- [x] Тени рельефа у терминатора.
- [x] Зернистость покрова суши (4-й канал кэша B): рваные границы биомов, пятнистый тон внутри.
- [x] Доменное искажение ослаблено для мелких октав: берега остаются «тектоническими», а детали не смазываются в полосы.
- [x] Огни городов — россыпи точек вместо равномерных пятен.
- [x] Дизеринг итогового кадра.

### Шаг 13. Три языка интерфейса (EN / RU / UZ)
- [x] `src/i18n.js`: три словаря по одним и тем же ключам (≈ 85 строк на язык) — подписи, группы, слайдеры, телеметрия и её
      единицы, ракурсы, кнопки, подсказки, названия/классы/описания архетипов, сообщения загрузки и ошибок, `aria-label`, заголовок вкладки.
- [x] Переключатель `EN · RU · UZ` вверху по центру (в подсказке кнопки — название языка на нём самом).

Живые цифры, снятые пока окно было видимо (ещё до второго прохода): монитор 144 Гц, 88 FPS при 1920×1080.
Регулятор разрешения прогнан на имитации 144 Гц (кадры подавались с шагом 1/144 с): с орбиты он держит масштаб 0.95
(1824×1026, 5.5 мс), на крупном плане — 0.75 (1440×810, 5.7 мс), без колебаний. На 60 Гц бюджет 13.3 мс, то есть
полное разрешение во всех ракурсах.

Мобильные раскладки, кадрирование и профили качества проверены отдельно — таблица в разделе 5 [DEPLOY-PLAN.md](DEPLOY-PLAN.md).

Чего **не** удалось проверить: частоту кадров на настоящих телефонах и планшетах (в эмуляции меняется только размер
окна); счётчик FPS в видимом окне после второго прохода — панель предпросмотра была скрыта,
и браузер придерживал `requestAnimationFrame`. Поэтому «после» — это время GPU на кадр, а не показание FPS на экране,
а регулятор проверен на имитации частоты, не на живом мониторе.

## 4. Запуск

```powershell
node tools/serve.mjs
```

Затем открыть `http://localhost:5173`. Сервер печатает и адрес в локальной сети — его можно открыть на телефоне в том же Wi-Fi.
Либо собрать проект и открыть `dist/planet-generator.html` двойным кликом.

Собрать сайт (папка `dist/`):

```powershell
node tools/build-single.mjs
```

Деплой: репозиторий импортируется в Vercel без настроек — команда сборки и папка результата записаны в `vercel.json`
(порядок действий — DEPLOY-PLAN.md, раздел 7).

## 5. Известные ограничения

- Рельеф в полёте — геометрия до ~1,2 м на вершину (`high`), мельче — узоры в пикселе; формы крупнее ~10 км
  берутся из кэша 1024² на грань, поэтому с малой высоты дальние хребты мягче ближних.
- Разрешение кэша рельефа — 1024² на грань (~1.5 мрад на тексель). Ближе этого детали дорисовывает микрорельеф из шума; он правдоподобен, но не продолжает крупные формы.
- Облака при сильном приближении всё ещё мягче поверхности: кэш 768² на грань, края дополняются шумовой эрозией.
- На встроенной графике и мониторе 144 Гц крупные планы идут в пониженном разрешении (≈ 0.75): полный кадр там стоит 9 мс при бюджете 5.6 мс.
- Тени облаков — одна проба плотности, без объёмного марша.
- В полёте на встроенной графике при прогонах заданий дважды терялся контекст WebGL; отдельно не воспроизвелось.
  Восстановление работает, снимок из полёта ограничен 2560 px.
- Наклон телефона и автопилот по касанию в эмуляции не проверить — нужна проверка на устройстве.
- Сдвиг оттенка атмосферы окрашивает и дымку над диском, поэтому при больших сдвигах океан меняет цвет вместе с небом.
- Нужен WebGL2 с рендером в half-float (`EXT_color_buffer_float`/`half_float`) — есть на любом современном десктопе и в актуальных мобильных браузерах; если нет, вместо чёрного экрана показывается сообщение.
- Плавность на настоящих телефонах и планшетах не измерялась (см. раздел 6 в DEPLOY-PLAN.md).
- Сообщения об ошибках запуска переведены, но сам путь ошибки (нет WebGL 2, сбой компиляции шейдера) на трёх языках вживую не воспроизводился.
- Узбекский перевод сверен по терминам (uz.wikipedia), но носителем языка не вычитан.
